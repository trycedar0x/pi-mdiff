| Here are the things I use (with the package config to import them). Most all of<br>my `~/.pi/agent/` can be found in my dotfiles ( [NonlinearFruit/dotfiles](https://github.com/NonlinearFruit/dotfiles/tree/master/pi)).<br>Caveman for short responses<br>`/caveman` let's you configure how brief the AI should be in its response.<br>Wading through pages of AI text is the bane of my existence. Using<br>`/caveman ultra` helps a ton!. This is the packages config:<br>```<br>"git:github.com/v2nic/pi-caveman",<br>```<br>Filter output and security from [@michalvavra](https://github.com/michalvavra)<br>- Filter output automatically catches some sensitive values (like GitHub tokens)<br>  <br>  <br>  and redacts them before it is given to the AI.<br>- Security blocks dangerous commands (eg: `sudo`) by requiring explicit user approval<br>This is the packages config:<br>```<br>{<br>  "source": "git:github.com/michalvavra/agents",<br>  "extensions": [<br>    "agents/pi/extensions/filter-output.ts",<br>    "agents/pi/extensions/security.ts"<br>  ],<br>  "skills": [],<br>  "themes": [],<br>  "prompts": []<br>}<br>```<br>Review and whimsical extensions by [@mitsuhiko](https://github.com/mitsuhiko)<br>- Review makes it easy to ask the AI to review a diff or commit or PR<br>- I love whimsical! It just replaces the `thinking...` text with funny random<br>  <br>  <br>  things like `Hiking through the headers...`. No functional purpose but totally<br>  <br>  <br>  worth it.<br>This is the packages config:<br>```<br>{<br>  "source": "git:github.com/mitsuhiko/agent-stuff",<br>  "extensions": [<br>    "extensions/review.ts",<br>    "extensions/whimsical.ts"<br>  ],<br>  "skills": [<br>    "skills/frontend-design"<br>  ],<br>  "themes": [],<br>  "prompts": []<br>}<br>```<br>Refactor and Story time by [@github](https://github.com/github)<br>- Refactor is suppose to improve making structural changes that don't change<br>  <br>  <br>  function. But I'm not convinced it helps (yet).<br>- Story time is a nice skill for summarize a repo and it's history and it's<br>  <br>  <br>  contributors. Could be helpful when you are the new guy.<br>This is the packages config:<br>```<br>{<br>  "source": "git:github.com/github/awesome-copilot",<br>  "skills": [<br>    "skills/refactor",<br>    "skills/repo-story-time"<br>  ],<br>  "extensions": [],<br>  "themes": [],<br>  "prompts": []<br>}<br>```<br>Superpowers from [@obra](https://github.com/obra) (not tested yet)<br>I haven't tried these in pi yet, so I'm not sure if they will work or not, but<br>friends have recommended trying it.<br>This is the packages config:<br>```<br>{<br>  "source": "git:github.com/obra/superpowers",<br>  "skills": [<br>    "skills/test-driven-development",<br>    "skills/writing-plans",<br>    "skills/writing-skills"<br>  ],<br>  "extensions": [],<br>  "themes": [],<br>  "prompts": []<br>}<br>```<br>Permission by [@prateekmedia](https://github.com/prateekmedia)<br>This is another great security tweak. By default your sessions will be read only<br>and you will get a popup to approve (once, always, never type deal) edits and<br>things like that. Having control like this makes using the AI a little less<br>terrifying.<br>This is the packages config:<br>```<br>{<br>  "source": "git:github.com/prateekmedia/pi-hooks",<br>  "extensions": [<br>    "permission/permission.ts"<br>  ],<br>  "skills": [],<br>  "themes": [],<br>  "prompts": []<br>}<br>```<br>YouTube transcript by [@badlogic](https://github.com/badlogic)<br>Little skill that lets the AI pull down YouTube transcripts. Helpful when<br>management sends you videos to watch that are more than 2-3 minutes.<br>This is the packages config:<br>```<br>{<br>  "source": "git:github.com/badlogic/pi-skills",<br>  "skills": [<br>    "skills/youtube-transcript"<br>  ],<br>  "extensions": [],<br>  "themes": [],<br>  "prompts": []<br>}<br>```<br>Save last, answer, cursor rules from me!<br>- Save last: Saves the last AI response to a text file `/save-last` or<br>  <br>  `/save-last foo.txt`. Once it is a text file, I can open it in my editor and<br>  <br>  <br>  boil it down to something helpful or just reference it later.<br>- Answer: Pull questions out of the previous AI response and ask them to the<br>  <br>  <br>  user one at a time, letting the user write answers. Once all questions are<br>  <br>  <br>  answered, send the question + answers to the AI. This is great for when the AI<br>  <br>  <br>  ends with 5 or 6 questions and you're lazy.<br>- Cursor rules: Loads cursors style rules when touching matching files<br>  <br>  <br>  (theoretically). A lot of slop in this one, be careful. But helpful when<br>  <br>  <br>  working in a Cursor heavy codebase.<br>I symlink these to the extensions folder but this config would probably work:<br>```<br>{<br>  "source": "git:github.com/NonlinearFruit/dotfiles",<br>  "extensions": [<br>    "pi/save-last-extension.ts",<br>    "pi/answer-extension.ts",<br>    "pi/cursor-rules-extension.ts"<br>  ],<br>  "skills": [],<br>  "themes": [],<br>  "prompts": []<br>}<br>``` |

| For fans of [Matt Pocock](https://github.com/mattpocock/skills)'s `/grill-me` skill, it pairs really well with the [rpiv-ask-user-question](https://pi.dev/packages/@juicesharp/rpiv-ask-user-question) Pi extension, but you need to tweak the `/grill-me` SKILL.md slightly:<br>Tweaked grill-me skill<br>```<br>---<br>name: grill-me<br>description: Interview the user relentlessly about a plan or design until reaching shared understanding, resolving each branch of the decision tree. Use when user wants to stress-test a plan, get grilled on their design, or mentions "grill me".<br>---<br>Interview me relentlessly about every aspect of this plan until we reach a shared understanding. Walk down each branch of the design tree, resolving dependencies between decisions one-by-one. For each question, provide your recommended answer.<br>Ask the questions one at a time.<br>If a question can be answered by exploring the codebase, explore the codebase instead.<br>## Question delivery<br>Prefer the `AskUserQuestion` tool over plain text when the question has a discrete set of plausible answers. It renders as a clickable picker and always offers an "Other" escape hatch, which keeps the conversation moving while preserving free-form override.<br>- Still **one question per turn**, even though `AskUserQuestion` accepts up to four. Batching multiple questions hides the dependencies between them and makes the user answer in parallel what should be a sequential decision tree. Walk the tree one branch at a time.<br>- Always lead with the recommended option labelled `(Recommended)` and explain *why* in its description.<br>- Use the `preview` field for ASCII mockups, code snippets, or layout sketches when the choice is visual or structural — side-by-side preview makes trade-offs concrete.<br>- Fall back to plain text only when the question is genuinely open-ended (e.g., "what are the use cases?") and a 2–4 option list would feel forced.<br>```<br>If you are unfamiliar with the `/grill-me` skill, I can recommend [this video](https://youtu.be/v4F1gFy-hqg). |
